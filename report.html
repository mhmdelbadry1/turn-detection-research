Two clocks: pause-EOT and overlap

A note on when a voice agent should start speaking, and when it should yield. Measurements, listen clips, and a small runtime for the overlap head — not a product ticket.

01 — Bottom line

Two heads

Two different questions, on two different clocks. Fusing them into one score hurt the pause job — see negative results above.

Pause head

Fires when: user goes silent
  • Model: Smart Turn v3.2 on 1.4.5
  • v1-mini is more accurate if the fork is dropped on 1.6.10
  • Status: stock v3.2 is the supported finding

Overlap head

Fires when: TTS is already playing
  • Model: VAP, English checkpoint, streaming CPC
  • 5 s transformer window (default)
  • Status: later — runtime is ready, not shipped

VAP should run for the whole call; gate the action, not the forward pass. The CPC encoder is unreliable for the first 1–2 s after a cold start, so starting it at TTS onset makes it worst exactly when barge-ins happen. Once VAP says yield inside a TTS island, stay muted until that island ends — on/off muting stutters. Feed VAP the TTS reference at playout, not at generation: generation-time audio leading the ear by hundreds of ms looks like overlap to the model.

VAP, one paragraph

Voice Activity Projection (Ekstedt & Skantze, KTH). Stereo: ch0 = user, ch1 = agent. Every 20 ms it emits p_now = P(that speaker talks in the next ~0.4 s). Yield while TTS plays when p_user > p_agent. The streaming implementation here persists the CPC encoder (~90% of cost) and re-runs transformers only on the last 5 s: 0.187 cores per concurrent call at 10 Hz on an M5 — down from 2.0 naive. Quantization was tried and rejected. On the 51Talk call, VAP alone does not skip an isolated «آه»; VAP plus a pause head does.

02 — The work

From the beginning

Dates are 2026. fact = measured or read from source. as reported = production state from an internal 2026-09-01 note, not re-checked against the cluster in this work. opinion = interpretation.

What production does today as reported

Turn detection in agent-service is NAMO alone, not a NAMO + Smart Turn hybrid. Smart Turn was stubbed in Feb 2026 (b860211b) to save CPU. The inference server hardcodes {"eou_probability": 0.5}. Override logic in agent-service is dead.

NAMO v1 Multilingual is text-only: it scores the STT transcript, never hears audio. Published standalone accuracy: 84.9% Arabic (weakest of 23 languages except Bengali), 90.9% English. Because it never hears audio, every Arabic STT error becomes a turn-taking error.

Krisp VAD stays in any design — min-silence in prod is 0.45 s. Pause classifiers fire after VAD reports silence. Provider mode (the STT vendor decides end-of-turn) already works and was out of scope.

Why this comparison

Customers barge in, fill, and hold. NAMO cuts them off or waits too long. The audio pause model under consideration was Smart Turn v3.2 (BSD-2, 8 MB ONNX, trainable). The accuracy winner in public numbers was LiveKit v1-mini, usable only inside LiveKit Agents 1.6.x (production pin: 1.4.5). Public bench of record: eot-bench (LiveKit, Apache-2.0) — false-cutoff rate at a 300 ms latency budget. We reproduced it.

Experiments, in order

  1. 2026-09-02 — Reproduce eot-bench (Smart Turn + v1-mini, Arabic + English). Matched the published leaderboard exactly.
  2. NAMO on the same harness (first number). Worse than doing nothing (VAD baseline).
  3. Last-token text gates on lagged STT. Same structural problem as NAMO; didn't beat audio-only.
  4. One Breez 51Talk call with separate human/agent tracks (n=1). Overlap 7.5 s. Public eot-bench doesn't score overlap — this call's pain is different.
  5. VAP offline on that stereo pair. First listen mixes sounded like the overlap yield wanted. VAP-only still started TTS after «آه»; adding a pause head skipped it.
  6. Score-fusion of VAP + Smart Turn on eot-bench. Hurt Arabic.
  7. CPU of naive VAP. 1–2 cores per concurrent call. Quantization doesn't fix it — cost is the CPC encoder (~90%), not the transformers.
  8. Streaming VAP (this package's runtime). ~10× cheaper. 1 s transformer sounded worse on overlap; 5 s recovers it and still holds 10 Hz.

What we did not do

  • No Smart Turn or VAP training.
  • No 300–500 Gulf export (not available for this work).
  • No EKS CPU re-measure.
  • No duration-heuristic baseline for overlap.

02 — The work

Architecture: two heads, two clocks

The full detail behind the "two heads" summary — why VAP must run continuously, channel alignment, and the cost shape.

The two jobs

  1. Pause-EOT. The user went quiet. Is the turn over so we may start TTS? This is what eot-bench scores, and what NAMO / Smart Turn / v1-mini do. They run after VAD silence.
  2. Overlap / barge-in. TTS is already playing. Is the user grabbing the floor, or just «eh» / «آه»? eot-bench cannot score this — no agent channel. This is what VAP is for.

Fusing them into one probability hurts the pause job. Keep two clocks:

all call:
  Krisp VAD on user
  Smart Turn when VAD says silence  →  may start TTS
  VAP on stereo (user + TTS-at-playout)  →  scores only; no action yet

while TTS playing:
  if VAP p_user > p_agent:  yield, sticky until this TTS island ends

Why VAP must run even when it must not act

VAP is causal over a rolling stereo context. The CPC encoder is unreliable for the first ~1–2 s after a cold start — the research adapter needed 2.1 s of left-pad before features were usable. If you start VAP at TTS onset, it is worst exactly when barge-ins are most likely. Consume audio all call; gate the mute, not the forward pass.

Channel alignment

VAP assumes ch0 and ch1 are aligned as the user heard them. In production, ch1 should be the TTS reference at playout, not at generation — generation can lead the ear by hundreds of ms (network + jitter buffer), which looks like overlap to the model.

hypothesisAfter a yield, Smart Turn's 8 s window may contain a period when the agent was audible. Feed the Krisp-cleaned user channel; consider trimming the window to post-yield audio — not measured.

Sticky yield

Once a TTS island is interrupted, stay interrupted. On/off muting stutters. The listen mixes use this policy.

Cost shape

Smart Turn fires a few times per minute (~22 ms each). VAP is a 50 Hz encoder for the whole call. Naive implementation: 1–2 CPU cores per concurrent call. Streaming CPC: ~0.19 cores at 5 s / 10 Hz on an M5. Re-measure on EKS before capacity planning. Quantization is the wrong lever — see VAP runtime.

What we still have not beaten. The honest overlap baseline is "ignore user speech shorter than ~300 ms while TTS plays." If that catches the same backchannels as VAP, VAP has to earn its 0.19 cores. Unmeasured.

03 — VAP deep-dive

The silent-ch1 54.8%, explained

This number gets quoted a lot in this report as "VAP ≈ VAD baseline" — here is exactly how it was produced, so it doesn't get over-read as "VAP failed."

Setup

eot-bench audio is user-only. VAP wants stereo. The adapter (eot-bench/eot_harness/vap_adapter.py):

  1. User wav → channel 0
  2. Zeros → channel 1 (KTH's own add_zero_channel helper)
  3. Run the English Switchboard checkpoint
  4. p_eot = mean of p_now channel 1 over the last 200ms — "would the imaginary other speaker start in the next ~0.4s?"

Transcripts unused. Score point 0.2s. Prefix ≤20s. That is a pause-EOT hack. On 51Talk, real agent audio was fed on ch1 — a different experiment.

Why 54.8%

eot-bench sweeps threshold × silence delay × timeout, then picks the point with mean latency ≤300ms and the fewest false cutoffs. The Arabic VAP operating point from the report: threshold 0.000 (every score "fires"), action_delay 0.300s, detect 100%. That is "wait 300ms of silence, always cut" — the VAD timer. VAD baseline Arabic FC@300ms is also 54.8%.

English: threshold 0.19, FC 50.2% vs VAD 55.6% — scores did a little; still near a silence timer, far behind Smart Turn.

What it means. With no agent channel, "will the other speaker start?" is mostly how long the user has been quiet — the timer already knows that. This does not measure barge-in, and it does not mean VAP has no signal with a real second channel — that specific experiment (VAP-alone, real stereo, pause-EOT) has not been run.

What breaks

  1. The methods a fork would override are gone. 1.4.5 used start()/push_audio()/update_options(); 1.6.10 calls _start()/_push_audio()/_update_options(). A 1.4.5-style subclass silently no-ops after the bump — no crash, just dead turn detection.

  3. Two detector protocols now — text (_TurnDetector, still supports NAMO) and streaming (_StreamingTurnDetector, v1/v1-mini). Plugging a text detector no longer needs a fork at all.
  4. The default flipped. Self-hosted with no detector passed now auto-selects v1-mini. Trap: bump the SDK, forget to pass a detector, and the process silently runs v1-mini.
  5. RecognitionHooks grew — new callbacks for interruption, backchannel, transcription timeout, EOT prediction. Any Breez hook object that isn't a full AgentActivity is now incomplete.
  6. Adaptive interruption is a third, separate model. InterruptionOptions.mode="adaptive" classifies barge-in vs backchannel — not v1-mini, not VAP, unmeasured on Arabic. hypothesis — the bump doesn't automatically supply an overlap head.
  7. Krisp is compatible. Streaming detector needs vad.min_silence_duration ≥ 0.25s; prod Krisp is 0.45s, so it clears. Keep passing Krisp explicitly so 1.6 doesn't substitute Silero.

What a VAP fine-tune would need

scoped from papers + trainer docs. No training run. VAP can be improved, and a domain-adapted VAP can become the overlap head. It should not replace Smart Turn until pause-EOT is measured on real stereo (user + TTS), which eot-bench cannot do. The 300–500 Gulf turns planned for Smart Turn are the wrong grain for VAP training.

What "rely on VAP" actually means

VAP does not output "turn complete." It outputs who will be voiced in the next ~0.2–2s.

UseRuleNeeds fine-tune?
Overlap (TTS playing)yield if p_user > p_agent, stickyDomain gap is user-vs-TTS, not two humans. Yes, for Gulf barge-in / «آه»
Pause / S-H (both quiet)next speaker from p_nowHypothesis. Silent-ch1 VAP = VAD on eot-bench. Stereo VAP with real agent history is unmeasured

Fact, from Inoue et al., LREC-COLING 2024: a VAP trained on one language does not transfer to another. A single model trained on all languages together matches the monolingual models. So "multilingual" means mix the hours in one training run, not train English and hope Arabic works.

What you fine-tune

Architecture: frozen CPC encoder (English Libri-light/Librispeech pretrain) → per-channel self-attention → cross-attention → two heads (256-way VAP state + 2-way VAD). Inoue's train.py flag --vap_freeze_encoder 1 keeps CPC frozen — you train transformers + heads. Loss: L = L_vap + L_vad. Labels are per-channel VAD, not complete/incomplete text.

Do not freeze the transformers if the domain is Gulf telephony vs Switchboard. Do not channel-flip 50/50 the way human–human VAP does — user and TTS are not interchangeable. Keep ch0=user, ch1=TTS at playout.

hypothesisOptional second fine-tune (Inoue BC models): same encoder, replace p_now/p_future with p_bc_react/p_bc_emo — needs backchannel tags ~500ms ahead. That's how you might teach «آه» without Smart Turn. Japanese ERICA WoZ only so far.

hypothesis, not published

  • Eval: tens of dual-track sessions (minutes each), held out — not 400 isolated turns.
  • Train, first try: on the order of 10–30h of Gulf user+TTS stereo, mixed with public hours.
  • Train, paper-scale: ~90h in-domain, matching their per-language budget.
  • The Smart Turn export of 300–500 turns is clips, not 90h of stereo — use it to score overlap/S-H, not to train VAP.

Data preparation

1. Sessions, not clips. Each call is one stereo WAV covering the whole session: 16kHz 16-bit, ch0 = Krisp-cleaned user, ch1 = agent TTS as played (not as generated). If ch1 leads the ear by hundreds of ms, the model learns fake overlap.

2. Per-channel VAD lists — the only required labels. One JSON per session:

[
  [[t0, t1], [t2, t3], ...],  # user voiced intervals, seconds
  [[t0, t1], ...],            # agent/TTS voiced intervals
]

Source: energy/VAD on each track independently. Do not label from STT complete/incomplete.

3. Sliding CSV — columns audio_path, start, end, vad_list, session, dataset. Each row = 20s of audio; vad_list must cover 22s (20s + 2s horizon), or the last 2s of every chunk has no target. Splits by session, not by row — never put two windows from the same call in train and test.

4. Legal. Customer audio stays private. Public Switchboard/HKUST/Fisher are LDC-licensed; Candor is CC BY-NC. Inoue's shipped weights are academic-only — fine-tuning into a production checkpoint needs a license path. Unknown — legal.

Already ruled out

  • Train on 400 turns — too small, wrong label type.
  • Silent agent channel — that's VAD.
  • 1s transformer as the overlap default (51Talk).
  • Expecting an English checkpoint to "just work" on Arabic (cross-lingual loss jumps in the paper's own table).
05 — Reference

VAP runtime

The optimized overlap head, ready to copy into agent-service (or a sidecar) as a starting point. Not wired to LiveKit. Third-party code under third_party/vap/ is KTH Voice Activity Projection (Erik Ekstedt); the Switchboard training dump is not included.

Before → after

Every 100ms, the naive version concatenated new audio onto a rolling N-second buffer and ran the entire forward pass: CPC convs + LSTM + downsample + both transformers + heads. Profile: CPC encoder ~90% of the forward, both transformers ~9.4%. A perfect transformer KV-cache is therefore capped at ~10% savings — that's why one wasn't built.

MethodSizeFidelitySpeed
fp3222.1 MB—baseline
Torch int8 (qnnpack, Linear only)11.9 MBr 0.9999, 99.8% agree0.76× slower
ONNX int8−3.4%r 0.58, 77% agreebroken
ONNX fp32samebit-exactviable export later

On Apple Silicon, torch int8 needs torch.backends.quantized.engine = "qnnpack" or you get NoQEngine. Still not worth it — the workload is not weight-bound. int8 never touches the CPC conv stack that dominates time.

Naive truncation of the waveform (just passing the last 1s in) does not match a 20s forward — agreement ~70–77%, flat from 10s down to 0.5s. That implicates lost CPC LSTM state, not transformer length; you cannot make it cheaper by shortening the wav you feed.

What the streaming wrapper does

  1. Overlap-save gEncoder (strided convs are not causal) — look back 4 hops (640 samples), hold back the last 2 hops (20ms) until the next chunk supplies right-context. Leftover-only chunking mismatched offline by mean abs ~0.4; overlap-save matches to ~1e-6.
  2. LSTM hidden per channel. The two stereo channels share one EncoderCPC — keepHidden=True is never set on that shared module, or channel 0 would leak into channel 1.
  3. Causal downsample tail so 100Hz → 50Hz matches the offline conv.
  4. Transformers see only the last transformer_ctx_sec of 50Hz features — default 5.0s.

Fidelity: encoder features match offline to max abs 3e-6; p_now vs the same transformer window (holdback-aligned) is bit-exact (r=1, 100% agree). 1s vs 20s transformer still disagrees ~18% of frames — they are not the same model; that's what showed up as missed barge-in at 1s.

What this is not

  • Not quantized (tried; rejected above)
  • Not ONNX (fp32 export was bit-exact and is a possible later format; int8 ONNX broke the model)
  • Not an Arabic fine-tune
  • Not a KV-cache transformer (wrong lever — CPC is 90% of the cost)

Still open

Consolidated from the scope note and the recommendation — the questions this study could not close.

  1. A held-out Gulf/Levantine eval set (hundreds of real turns). The only gap that can reorder the pause-head ranking — public eot-bench Arabic is not this traffic.
  2. Whether LiveKit Agents 1.6.x is worth taking for v1-mini. That path means dropping the AudioRecognition fork, not re-porting it.
  3. VAP as an overlap head, behind a flag, after it's compared to a duration heuristic. English checkpoint, n=1 Gulf call so far.
  4. CPU on production Linux nodes, before any capacity claim — everything here is one Apple M5.
  5. Duration-heuristic overlap baseline: ignore user speech shorter than ~300ms while TTS plays. VAP has to beat that rule, not beat doing nothing.
  6. Adaptive interruption in LiveKit 1.6.x (InterruptionOptions.mode="adaptive") — a third model, unmeasured on Arabic. The SDK bump does not automatically supply an overlap head.
  7. Every other LiveKit patch in agent-service. Those, not EOU, dominate the real cost of 1.6.x. The service tree was not on the machine used for this work.
